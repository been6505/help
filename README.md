# HELP ME 4U · Partner Trust & Verification

ระบบรับสมัครและตรวจสอบองค์กรที่จะเข้าร่วม HELP ME 4U: มูลนิธิ สมาคม หน่วยงานรัฐ War Room กลุ่มอาสาอิสระ และบริษัท/CSR

> **ทุกองค์กรสมัครได้ แต่ไม่มีใครได้สิทธิ์เข้าถึงข้อมูลผู้ประสบภัยโดยอัตโนมัติ**
> ใบสมัครใหม่อยู่ที่ระดับ L0 เสมอ จนกว่าแอดมินจะตรวจหลักฐานครบและอนุมัติ ไม่ต้องรอผู้ประสานงานระดับจังหวัด

เว็บ static (HTML/CSS/JS ล้วน ไม่ต้อง build) ใช้ Google Apps Script + Google Sheet เป็นฐานข้อมูล เหมือน UM+

## หน้าต่างๆ

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ฟอร์มสมัคร 5 ขั้น (ประเภท → ผู้รับผิดชอบ → พื้นที่/ความสามารถ → หลักฐาน → ข้อตกลง) และหน้าติดตามใบสมัคร/ส่งข้อมูลเพิ่ม |
| `admin.html` | Admin Verification: คิว, ตรวจ checklist, ขอข้อมูลเพิ่ม, อนุมัติพร้อมระดับสิทธิ์, ไม่อนุมัติ, ระงับ/คืนสิทธิ์, Audit Log |
| `assets/core.js` | **กฎทั้งหมดของระบบ** (สถานะ, เพดานสิทธิ์, checklist) ใช้ร่วมกันทั้งเบราว์เซอร์และเซิร์ฟเวอร์ |
| `assets/api.js` | ตั้งค่า `API_URL` และฐานข้อมูลจำลองสำหรับโหมดทดลอง |
| `backend/Code.gs` | Apps Script: เก็บข้อมูลลง Google Sheet, ไฟล์หลักฐานลง Google Drive, ตรวจรหัสแอดมิน |

## ลองบนเครื่อง (โหมดทดลอง)

```sh
python3 -m http.server 8000
# สมัคร:  http://localhost:8000/
# แอดมิน: http://localhost:8000/admin.html  (รหัส demo)
```

เมื่อ `API_URL` ใน `assets/api.js` ว่าง ระบบใช้ข้อมูลตัวอย่าง 5 องค์กรที่เก็บในเบราว์เซอร์ ทดลองติดตามใบสมัครได้ด้วย `HM-6910-T8VN` รหัส `DEMO2026`

## เชื่อมฐานข้อมูลจริง

1. สร้าง Google Sheet ใหม่ (เช่น "HELP ME 4U Partners") → Extensions → Apps Script
2. สร้างไฟล์ `Core.gs` วางเนื้อหา `assets/core.js` ทั้งไฟล์ และไฟล์ `Code.gs` วางเนื้อหา `backend/Code.gs`
3. เลือกฟังก์ชัน `setup` แล้วกด Run อนุญาตสิทธิ์ Sheet/Drive ระบบจะสร้างชีต `Partners`, `AuditLog`, โฟลเดอร์เก็บหลักฐาน และรหัสแอดมินแรก (ดูใน Execution log)
4. Project Settings → Script Properties → `ADMIN_KEYS` ใส่แอดมินแต่ละคนเป็น `ชื่อ:รหัส` คั่นด้วยจุลภาค (รหัสยาว 16 ตัวขึ้นไป แยกคนละรหัส เพื่อให้ Audit Log บอกได้ว่าใครตัดสินใจ)
5. Deploy → New deployment → Web app → Execute as: **Me**, Who has access: **Anyone** → คัดลอก URL
6. ใส่ URL ใน `API_URL` ของ `assets/api.js` แล้วขึ้นเว็บ (เช่น GitHub Pages)

เมื่อแก้ `assets/core.js` ต้องคัดลอกไปทับ `Core.gs` และ Deploy เวอร์ชันใหม่ทุกครั้ง

## ฐานข้อมูล

**ชีต `Partners`** หนึ่งแถวต่อหนึ่งใบสมัคร

| กลุ่ม | คอลัมน์ |
|---|---|
| ระบบ | `id` (HM-ปีเดือน-XXXX), `created_at`, `updated_at`, `status`, `level`, `requested_level`, `reviewer`, `decided_at`, `token_hash` |
| องค์กร | `org_type`, `org_name`, `reg_no`, `parent_agency`, `founded_year`, `members`, `about` |
| ผู้รับผิดชอบ | `contact_name`, `contact_role`, `contact_phone`, `contact_email`, `contact_line`, `backup_name`, `backup_phone` |
| พื้นที่/ความสามารถ | `province`, `districts`, `address`, `capabilities`*, `resources`, `availability` |
| หลักฐาน | `docs`* (ชื่อไฟล์ ประเภท และ Drive file id), `links`*, `referee`, `responses`* (คำตอบเมื่อถูกขอข้อมูลเพิ่ม) |
| การตรวจ | `agreements`*, `agreed_at`, `checklist`*, `admin_note` (ภายใน), `info_request` (ผู้สมัครเห็น), `suspended_reason` |

\* เก็บเป็น JSON

**ชีต `AuditLog`** ทุกการเปลี่ยนแปลง: `ts`, `partner_id`, `actor`, `action`, `from_status`, `to_status`, `from_level`, `to_level`, `note`, `public` (1 = ผู้สมัครเห็นข้อความนี้)

## สถานะและสิทธิ์

```
pending ──เริ่มตรวจ──▶ reviewing ──อนุมัติ (L1–L3)──▶ approved ──ระงับ──▶ suspended
   │  ▲                   │                            │  ▲                 │
   │  └─ผู้สมัครส่งข้อมูลเพิ่ม─ need_info ◀─ขอข้อมูลเพิ่ม─┘       └─เปลี่ยนระดับ┘   คืนสิทธิ์ ─▶ approved
   └──────────────ไม่อนุมัติ──────────▶ rejected (ยื่นใบสมัครใหม่ได้)
```

| ระดับ | สิทธิ์ |
|---|---|
| L0 | ไม่เห็นข้อมูลผู้ประสบภัย (ทุกใบสมัครที่ยังไม่อนุมัติ, ถูกระงับ หรือไม่อนุมัติ) |
| L1 | สถิติรวมรายเขต/อำเภอ ไม่มีชื่อ เบอร์ พิกัด |
| L2 | ชื่อ เบอร์ พิกัด เฉพาะเคสที่ถูกมอบหมาย ระหว่างปฏิบัติงาน |
| L3 | เคสทั้งหมดในพื้นที่ที่อนุมัติ และมอบหมายเคสให้ทีม L2 |

เพดานสิทธิ์ตามประเภท: มูลนิธิ / สมาคม / หน่วยงานรัฐ / War Room สูงสุด L3, กลุ่มอาสาอิสระ L2, บริษัท/CSR L1
ระบบไม่ยอมให้อนุมัติระดับใดจนกว่า checklist ที่ระดับนั้นกำหนดจะติ๊กครบ (เช่น L1 ต้องโทรยืนยันแล้ว + เอกสารหลักของประเภทนั้น, L2 ขึ้นไปต้องครบทุกข้อ) กฎนี้ตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ปุ่มบนหน้าเว็บ

## ความปลอดภัยที่มีแล้ว

- ผู้สมัครติดตามใบสมัครด้วยเลขใบสมัคร + รหัสติดตาม เก็บเฉพาะ hash (SHA-256 + salt) ในชีต
- แอดมินแต่ละคนมีรหัสของตัวเอง ชื่อใน Audit Log มาจากเซิร์ฟเวอร์ แก้จากหน้าเว็บไม่ได้
- ไฟล์หลักฐานเก็บในโฟลเดอร์ Drive ส่วนตัว เปิดได้เฉพาะคนที่แชร์โฟลเดอร์ให้ (อย่าตั้งเป็นสาธารณะ)
- จำกัดชนิด/ขนาดไฟล์, จำกัดการส่งซ้ำ (3 ใบสมัคร/ชม./เบอร์), honeypot กันบอท, กันสูตรแปลกปลอมในชีต, LockService กันเขียนชนกัน
- ตรวจพบเบอร์โทรหรือเลขทะเบียนซ้ำกับใบสมัครอื่นและแจ้งเตือนแอดมิน

## ยังต้องทำก่อนใช้งานจริง

- **เชื่อมระดับสิทธิ์กับ UM+/ระบบเคส**: ตอนนี้ระบบนี้บันทึกว่าองค์กรได้ระดับไหน แต่ API เคสของ UM+ ยังไม่ได้อ่านค่านี้ ต้องออกบัญชี/รหัสให้องค์กรที่อนุมัติแล้ว และให้ API เคสกรองข้อมูลตามระดับฝั่งเซิร์ฟเวอร์
- แจ้งผลผู้สมัครทาง SMS/อีเมลเมื่อสถานะเปลี่ยน
- ทบทวนสิทธิ์เป็นระยะ (เช่น หมดอายุทุก 6 เดือน) และกระบวนการอุทธรณ์
- ให้ผู้เชี่ยวชาญตรวจข้อกำหนด PDPA, ระยะเวลาเก็บเอกสาร และข้อตกลงแบ่งปันข้อมูลระหว่างองค์กร
